# 生产环境配置自动修复脚本使用说明

## 📋 脚本功能

`fix-production-env.sh` 脚本可以自动修复生产环境的配置问题：

1. ✅ 备份原始配置文件（带时间戳）
2. ✅ 删除重复的 API Key 配置
3. ✅ 生成新的 JWT_SECRET（替换占位符）
4. ✅ 验证修改结果
5. ✅ 设置配置文件权限为 600（安全）
6. ✅ 可选：重启应用（使用 PM2）

## 🚀 使用方法

### 方式一：直接执行（推荐）

```bash
# 1. 进入项目目录
cd /path/to/your/project

# 2. 给脚本执行权限（首次使用）
chmod +x scripts/fix-production-env.sh

# 3. 执行脚本
./scripts/fix-production-env.sh
```

### 方式二：通过 bash 执行

```bash
# 不需要执行权限，直接用 bash 运行
bash scripts/fix-production-env.sh
```

## ⚙️ 脚本特性

### 安全性
- ✅ 自动备份原始配置文件
- ✅ 使用加密安全的随机数生成器
- ✅ 设置文件权限为 600（仅所有者可读写）
- ✅ 所有操作都有日志记录

### 智能检测
- ✅ 自动检测重复配置
- ✅ 自动识别占位符密钥
- ✅ 支持多种密钥生成工具（openssl、node、python3）
- ✅ 自动检测 PM2 应用

### 错误处理
- ✅ 遇到错误立即停止（`set -e`）
- ✅ 清晰的错误提示
- ✅ 支持恢复备份

## 🔧 恢复备份

如果脚本执行后发现问题，可以恢复备份：

```bash
# 查看所有备份文件
ls -la .env.production.backup.*

# 恢复最新的备份
cp .env.production.backup.20250116_123456 .env.production

# 或者使用通配符恢复最新的备份
cp .env.production.backup.$(ls -t .env.production.backup.* | head -1) .env.production
```

## 📊 执行前检查

在执行脚本前，建议先检查当前配置状态：

```bash
# 检查 API Key 配置行数
grep -c "^COZE_WORKLOAD_IDENTITY_API_KEY=" .env.production

# 检查 JWT_SECRET 是否为占位符
grep "^JWT_SECRET=" .env.production

# 检查是否有重复配置
awk -F= '{print $1}' .env.production | sort | uniq -d

# 检查文件权限
ls -la .env.production
```

## 🎯 执行后验证

脚本执行完成后，建议进行以下验证：

```bash
# 1. 验证 API Key 配置
grep "^COZE_WORKLOAD_IDENTITY_API_KEY=" .env.production

# 2. 验证 JWT_SECRET（应该不再是占位符）
grep "^JWT_SECRET=" .env.production

# 3. 验证文件权限（应该是 -rw-------）
ls -la .env.production

# 4. 检查应用日志
pm2 logs --lines 50

# 5. 测试关键功能
# - 用户登录
# - 支付功能
# - AI 生图功能
```

## ⚠️ 注意事项

1. **执行前备份**
   - 脚本会自动创建备份，但仍建议手动备份重要配置

2. **重启应用**
   - 重启是可选步骤，建议选择 `y` 使配置立即生效
   - 如果使用其他进程管理工具，请手动重启

3. **对象存储配置**
   - 脚本不会自动添加对象存储配置
   - 需要根据实际情况手动添加

4. **生产环境操作**
   - 建议在低峰期执行
   - 执行前通知相关团队成员
   - 准备好回滚方案

5. **PM2 应用名称**
   - 脚本会自动查找 PM2 应用
   - 如果有多个应用，会重启第一个找到的
   - 建议确认应用名称或手动重启

## 🔍 常见问题

### Q: 脚本执行失败怎么办？
A: 检查以下内容：
1. 是否在项目根目录执行
2. .env.production 文件是否存在
3. 是否有文件读写权限
4. 使用 `bash -x scripts/fix-production-env.sh` 查看详细执行过程

### Q: 可以手动执行单个步骤吗？
A: 可以。脚本中的每个步骤都可以单独执行，参考脚本中的命令。

### Q: 脚本会修改哪些配置？
A: 脚本会修改：
1. 重复的 API Key 配置（删除重复项）
2. JWT_SECRET（如果检测到占位符）
3. 文件权限（设置为 600）

### Q: 如何确认修改已生效？
A: 检查：
1. 配置文件中的值是否已更新
2. 应用日志是否无错误
3. 功能测试是否正常
