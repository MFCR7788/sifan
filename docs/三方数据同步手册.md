## 三、日常操作

### 3.1 改代码 → 上线（最常用）

```bash
cd ~/Downloads/MFCR

# 1) 改代码
vim src/app/xxx/page.tsx

# 2) 本地预览（可选）
npm run dev            # 起在 5000 端口

# 3) 一键上线（含构建、打包、上传、重启、健康检查、失败回滚）
bash scripts/deploy-sifan.sh
```

脚本内部流程：`git pull` → `npm run build` → 打包 `.next`/`public` → `scp` → 服务器解包 → `pm2 restart sifan` → 健康检查（失败自动回滚）

**参数**

| 参数 | 用途 |
|---|---|
| 无参数 | 完整流程 |
| `--skip-build` | 跳过本地构建，只上传已有产物 |
| `--build-only` | 只在本地构建，不上传 |

### 3.2 只提交代码，不上线

```bash
cd ~/Downloads/MFCR
git add -A
git commit -m "feat: xxx"
git push origin main
```

> 服务器**不会**自动拉取（原因见第四节）。上线仍需执行 3.1。

### 3.3 改业务数据（数据库）

三端连的是同一个库，**任一端写入，三端立即可见**。

```bash
# 服务器上直接操作
ssh zjsifan
cd /root/sifan
node -e "
  const {Pool}=require('pg');
  const p=new Pool({connectionString:process.env.PGDATABASE_URL||require('fs').readFileSync('.env.production','utf8').match(/PGDATABASE_URL=\"?([^\"\n]+)/)[1]});
  p.query('SELECT now()').then(r=>{console.log(r.rows);process.exit(0)});
"
```

> 注意：服务器没装 `psql`，需要用 Node 的 `pg` 客户端连接。

## 四、两个硬约束（决定了架构形态）

### 约束 1：服务器无法完成生产构建

| 指标 | 数值 |
|---|---|
| 服务器总内存 | 1.8 GB |
| lingji 常驻占用 | ~90 MB（峰值 244 MB） |
| 构建时 node 进程峰值 | 1.24 GB → **被 OOM Killer 杀死（exit 137）** |
| 解决方案 | 本地 Mac（24 GB）构建后上传产物 |

已尝试过的缓解手段（均不足）：
- `NODE_OPTIONS=--max-old-space-size=900/1100` → 仍 OOM
- 构建期临时 `pm2 stop lingji` 释放内存 → 仍 OOM
- 扩容 Swap 到 6 GB → 只防崩溃，不解决构建失败

### 约束 2：服务器到 `github.com:443` 不通

| 目标 | 连通性 | 耗时 |
|---|---|---|
| `github.com` | ❌ 不通 | connect=0，持续超时 |
| `api.github.com` | ✅ 通 | 0.42 s |
| `registry.npmjs.org` | ✅ 通 | 2.95 s |
| 火山引擎 RDS:5432 | ✅ 通 | TCP 可达 |

**结论**：服务器无法 `git pull`，代码同步只能走「本地推 → 本地拉产物上传」。

### 附带影响

- GitHub Actions 直推服务器的方案**不可行**（Actions 在 GitHub 侧，回连服务器可行，但服务器拉不到代码仍需产物上传）
- 后续若要完全自动化，可考虑：GitHub Actions 构建产物 → 阿里云 OSS → 服务器定时拉取（服务器到 OSS 通常通畅）

### 5.2 ⚠️ 仍需人工处理：轮换密钥

**GitHub 仓库是 public，以上密钥在 2026-05-12 之前已公开暴露，且仍存在于 git 历史中。**
停止跟踪只阻止「未来」泄露，**不能消除历史记录**。必须轮换：

| 密钥 | 泄露影响 | 轮换入口 |
|---|---|---|
| `WECHAT_PAY_*`（含 APIv3 密钥 + 商户私钥） | **可伪造支付回调** | 微信商户平台 → API 安全 → 更换证书 |
| `ALIPAY_*`（当前值为空，暂无害） | 支付宝回调伪造 | 支付宝开放平台 |
| `JWT_SECRET` | 可伪造登录态 | 应用内重生成 |
| `COZE_WORKLOAD_IDENTITY_API_KEY` | AI 服务额度盗用 | Coze 平台 |
| 阿里云 `AccessKey` | 云资源操作 | 阿里云 RAM 控制台 |
| GitHub PAT `ghp_...` | 仓库读写权限 | GitHub Settings → Developer settings |

**若需彻底清除历史**：`git filter-repo` 重写历史 + 强制推送 + 通知所有克隆者重新克隆。
⚠️ 该操作会改变所有 commit SHA，且已部署的服务器需重新对齐，建议在完成密钥轮换后再做。

### 5.3 令牌处理约定

| 位置 | 方式 |
|---|---|
| 本地 Mac | macOS keychain（`git credential approve`），remote URL 不含令牌 |
| 服务器 | `/root/.git-credentials`（权限 600），remote URL 不含令牌 |
| 禁止 | 任何 `git remote -v` 输出中直接内嵌 `ghp_` |

## 六、服务器运维速查

```bash
ssh zjsifan          # 密钥登录，alias 已配好

# 应用状态
pm2 list                                    # 查看 sifan / lingji
pm2 logs sifan --lines 50 --nostream        # 查看官网日志
pm2 logs lingji --lines 50 --nostream       # 查看 lingji 日志
pm2 restart sifan                           # 重启官网
pm2 save                                    # 保存进程列表（开机自启用）

# nginx
nginx -t && systemctl reload nginx
cat /etc/nginx/conf.d/sifan.conf             # 站点配置
cat /etc/nginx/snippets/lingji-agent.inc     # lingji 长连接片段（已内联进主配置）

# 证书
certbot renew --cert-name www.zjsifan.com   # 手动续期
# 自动续期 crontab：12 3 * * * certbot renew --deploy-hook 'systemctl reload nginx'

# 数据库
grep PGDATABASE_URL /root/sifan/.env.production   # 查看连接串（勿外传）

# 回滚
cd /root/sifan && ls -dt .next.old.* | head        # 查看历史产物备份
```

## 七、故障排查

| 现象 | 排查步骤 |
|---|---|
| 官网 502 | `pm2 list` 看 sifan 是否 online；`pm2 logs sifan --err` 看崩溃原因 |
| 官网 404 / 白屏 | `ls /root/sifan/.next/BUILD_ID` 是否存在；产物是否完整上传 |
| 数据库连接失败 | `grep PGDATABASE_URL /root/sifan/.env.production`；`nc -zv <host> 5432` |
| 构建 OOM (exit 137) | 必须在本地构建，不要在服务器上 `npm run build` |
| 服务器 git pull 失败 | 预期行为，github.com:443 不通；改用 `deploy-sifan.sh` |
| 证书过期 | `certbot renew --cert-name www.zjsifan.com && systemctl reload nginx` |
